# grill-me for DSH

> 一个"逐题拷问"技能：对你的方案、规格或工单**一次只问一个问题**（每题 2–4 个具体选项、有证据才给推荐答案），每个确认的答案**先落盘再问下一题**，结束时给出**五维歧义报告 + 阈值门**。
>
> 目标只有一句话：**产出一个"零上下文的人照着就能干、不用再问"的东西。**

适用宿主：**DeepSeek Harness**（`-dsh` 版；依赖 `ask_user_question` / `read` / `write` / `edit`）。无外部依赖、不联网、无脚本。

---

## 它解决什么问题

方案、规格、工单常常"看着已经定了"，但换个人（或换一个 agent）去执行还是会走偏——因为**关键决定从来没被逐条问出来**，全留在作者脑子里。

grill-me 干的就是这件事：把隐含决定逼成**已确认的条目**，并给这份目标定义一个**可核验的歧义分**。它不产出方案，它**审问方案**。

## 什么时候**别**用它

| 情况 | 该走的路 |
|---|---|
| 需求还太模糊，连"要拷问什么"都说不清 | 先澄清，把靶子立起来 |
| 要**评审一份已定稿的方案** | 那是评审，不是拷问 |
| 只要文档 / README | 直接写；纯拷问本身不产文档 |
| 问"代码怎么跑 / 数据长什么样"这类事实 | 去查，不要问 |
| 只是想解除某个阻断性歧义（别的任务卡住了） | 歧义一解除就返回原任务，不继续拷问 |

## 安装

把这个仓库放进 DSH 的技能目录（目录名必须是 `grill-me`）：

```powershell
# Windows（默认 DSH 家目录是 C:\Users\<你>\.dsh）
git clone https://github.com/yuanfeng637-cmyk/grill-me-for-dsh "$env:USERPROFILE\.dsh\skills\grill-me"
```

```bash
# Linux / macOS
git clone https://github.com/yuanfeng637-cmyk/grill-me-for-dsh ~/.dsh/skills/grill-me
```

**放好后重开会话**（技能清单在会话建立时定版），清单里出现 `grill-me` 即可用。`SKILL.md` 是唯一的运行副本，其余文件是文档。

## 用法

任一触发词都行：

- 「**grill me**：<把你的方案粘进来>」
- 「拷问我这个方案 / 把这方案问穿 / 我有漏吗 / 风险在哪」

一次运行会这样走：

1. **首题之前**声明 checkpoint、备份、账目三者的路径与写入范围（位置未约定时先征求同意）；
2. 一次一个问题，每题 2–4 个具体选项；**只有证据支持某偏好时**才给推荐答案，否则明确写"无推荐答案"；
3. 每题确认后**一次写入**同时落下 Q&A 与恢复信息，**写之后新一次读**核验，然后才问下一题；
4. 说「够了 / 停」→ 立即打印报告退出。

**它往盘上写什么**（是特点也是代价）：工作区下 `grill\<日期>-<主题>.md`（拷问记录）与同目录的账目文件；改已有记录前先备份。要"不留痕"，直接说——切**无落盘模式**，摘要只留在会话内（**不保证跨会话恢复**）。

## 输出长什么样

运行结束会得到这样一份报告（数值是示例）：

```
歧义报告：
  评分对象及来源:          首次目标定义快照
  Goals（做什么）:         0.25 ✓  依据：……
  Acceptance（算完成）:    0.00 ✓  依据：……
  Boundaries（不许碰）:    0.00 ✓  依据：……
  Alternatives（排除项）:  0.50 ⚠  依据：……
  Assumptions（假设）:     0.25 ✓  依据：……
  ─────────────────────────────
  评分模式与阈值:          freeform 0.4
  聚合:                    0.20
  阈值检查:                通过 / 未通过（列失败条件）
  单维上限检查:            通过 / 未通过（列 >0.5 的维度）
  阻断性 Open Question:    无 / 逐条列出 + 责任人
  待保存项 / 待同步项:      无 / 逐条列出
  门状态:                  通过 / 未通过 / 未通过（评分不完整）
  退出原因:                ……
```

评分口径：五维（Goals / Acceptance / Boundaries / Alternatives / Assumptions）各 0–1，聚合＝五维均值；阈值 spec 0.2 / ticket 0.3 / freeform 0.4。**通过需三条同时满足**：聚合 ≤ 阈值、**任一维 ≤ 0.5**、**无阻断性 Open Question**。

## 成熟度与已知限制

- 版本 **v1.7.0-dsh**。做过**文本级**多轮评审与**一次 8 题空转功能测试**；**无落盘模式的路径尚未实测**。
- 规则**靠执行者自觉**：本技能不提供锁、事务或原子写入保证；同一 checkpoint 只允许一个写入者，独占无法确认时应停止写入。
- 空转测试暴露并已修掉两条：账目路径被误声明时无人拦（v1.7 改为写入前实测）、每问三次工具往返导致执行者跳步（v1.7 改为一次写入 + 一次核验）。
